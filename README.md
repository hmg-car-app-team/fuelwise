# 알뜰주유 FuelWise

주유소와 충전소까지 가는 데 드는 연료비까지 계산해, 단순 최저가가 아닌 "실제로 가장 이득인" 주유소와 전기차 충전소를 찾아주는 앱입니다.

> 현대자동차그룹 차량용 앱 개발 공모전 출품작. Pleos Connect(Android Automotive) 환경용 Android 앱입니다.

## 핵심 기능

- 실질 비용 = 단가 x 주입량 + 우회 연료/전력비 (기획서 예시 1,200원 - 850원 = 정확히 350원, 단위 테스트로 재현)
- 절약액의 비교 기준은 '근처 최저가'가 아니라 **우회가 가장 적은 후보**이며, 연비·전비는 차량 실측이 아니라 **사용자 설정값**으로 계산한다.
- **'경로상' 추천이 아니라 근사**: 기본은 현재 위치 20km 이내 후보를 직선거리x1.3 왕복 우회로 비교한다. 내비가 활성 안내 중이면 getDestinationInfo(읽기 전용, 2초 제한, 30초 간격 이상)로 실제 목적지를 받아 '현재→후보→목적지' 우회식에 넣고(표기 '경로 추정 우회(직선 근사)'), 응답 없음·실패·미지원이면 목적지 없음으로 폴백해 현재 위치 왕복으로 비교한다(표기 '왕복 추정(목적지 없음)'). 목적지가 있으면 반경 20km 밖이라도 목적지 방향 60km 이내이면서 우회 3km 이하인 후보를 더한다. 도로 경로 기반이 아닌 직선 근사이며, 실차·에뮬레이터에서 실제 응답은 확인하지 못했다(단위 테스트로 계산·폴백만 검증).
- 잔량 알림: 차량 SDK(Fuel %, EV SoC, 주행가능거리) 임계 이하 -> **내비 활성 경로를 먼저 확인** -> TTS 안내 -> 짧은 명시 응답("응", "네", "좋아요", "추가해줘", "안내해줘" 등)을 STT 1회 청취로 수락 -> 결과를 음성으로 확인.
  - 활성 경로 있음: `addWaypoint`, 문구 "경유지로 추가할까요?" / 없음: `requestRoute`, "안내를 시작할까요?" / 확인 불가(2초 무응답·미연결): `requestRoute`, "현재 경로를 바꿀까요? 바꾸려면 '바꿔줘'라고 말씀해 주세요"
  - 수락 규칙: 단어 전체 일치만 수락. '예약', '응급', '네비' 처럼 문장 속 일부는 수락 아님. "아니", "싫어", "취소", "괜찮아" 등 거절이 우선. '어'·'어어' 같은 머뭇거림과 물음표가 붙은 '네?' 는 수락이 아니다. 공백을 뺀 길이 **14자까지** 수락 표현의 연속이면 수락, **15자부터는 수락하지 않는다**(긴 문장 차단). **경로를 덮어쓸 수 있는 알림(경로 상태 확인 불가)** 에서는 '응/네/예/그래' 같은 단음절 수락을 허용하지 않고 "바꿔줘", "그렇게 해줘" 같은 다음절 명시 표현만 수락한다.
  - 배너 버튼: 알림 때 확인한 상태에 따라 "경유지로 추가" / "이 주유소(충전소)로 안내 시작" / "현재 경로를 바꾸기". **수동으로 누르면(배너·상세 버튼) 실행 직전에 경로 상태를 다시 확인**(2초)해 현재 상태 기준으로 동작하며, 확인 불가면 덮어쓰기 확인 팝업("진행 중인 경로가 있다면 바뀔 수 있어요.")을 거친다. 음성 수락만 알림 시점에 정한 동작을 쓴다(질문을 그 기준으로 했으므로).
  - **음성 응답 사용**(설정 > 알림, 기본 켜짐, 정차 중에만 변경): 끄면 알림은 화면 배너+TTS 로만 하고 마이크 청취를 하지 않으며 배너 버튼으로만 수락한다.
  - **후보 0개 알림**: 후보 로드가 **완료**됐는데 추천할 후보가 없으면(강남 밖·반경 밖) 잔량 임계에서 **1회** "잔량 부족 · 근처 후보를 찾지 못했어요"를 배너+TTS 로 알린다(수락·청취 없음, 이후 재무장 전까지 반복 없음). 후보 **로드 전·로드 실패 중에는 알림을 보류**하고 한 번 울린 것으로 치지 않는다(로드가 성공하면 그때 판단).
- 신호 안정화: 폴링이 실패해도 마지막 정상값을 30초 유지하고(신호가 사라진 뒤 30초 동안은 낡은 값이 '차량 신호'로 쓰인다), 자동 모드는 연료·전기 **두 도메인이 한 사이클(값 또는 실패/5초 무응답)을 마친 뒤** 마지막으로 확인된 도메인을 유지한다. 주행가능거리 0(값 없음) 응답은 실패로 세지 않아 3초 주기 폴링이 멈추지 않고, 값이 생기면 다음 주기에 반영된다. Vehicle 서비스 초기화 실패는 2초→최대 30초 백오프로 재시도하고, 서비스 연결 오류 뒤 재개 시 Vehicle 을 새로 만든다. 재시도 간격·TTL 은 단조 시계(`elapsedRealtime`)를 쓴다. 앱 시작/재개·권한 부여 시 일시정지된 폴링을 즉시 재시도한다. 콜백이 5초 안에 오지 않으면 실패로 센다.
- 에너지 모드가 자동이 아니면 헤더에 '(설정: 내연기관/전기차)' 가 표시된다. 시연 `mode` 는 메모리 전용이며 저장되지 않는다.
- 전기차 모드: 충전 출력(차량 한도)·대기·요금·시간 환산 반영
- 할인 카드/멤버십, 월 누적 '추정 절약' 리포트(**수동 '주유/충전 완료 기록' 기반**; 샘플 기록은 합계 제외, 같은 곳 60초 내 중복 기록 방지), 설정(연료 종류·탱크·연비 등), 상태 저장·복원
- 알림 배너는 모든 탭 상단에 표시되고, 음성이 끝나면 20초 뒤(또는 잔량 회복·재무장 시) 자동으로 사라진다.
- 주행 중에는 한 줄 배너(40자 이내, 절약액 포함)+음성 상태("음성 발화 중/듣는 중/수락/…")만. 정차 시 목록·상세. 앱은 **주행(DRIVING) 상태로 시작**하며 정차 신호가 확인되면 정차 화면으로 전환한다. 주행 중에는 토스트를 띄우지 않고 주행 진입 시 떠 있던 토스트·상세 화면을 닫는다(주행 중 세팅된 일반 안내는 버려진다; 예외로 '삭제 실패·저장 보류·복원 안내'만 보관했다가 정차 시 한 번 표시). 기어·UX 제한 신호를 모두 확인하지 못하면 항상 주행으로 간주해, 주행 화면에 '차량 상태를 확인하지 못하면 주행 중으로 간주해요' 한 줄을 표시한다(UX 제한 소스가 영구히 null 인 환경에서는 기어가 확인되지 않는 한 정차 화면이 열리지 않는다).
- Landscape 2분할(목록/상세) / Portrait 1단(목록->상세)

## 제출 빌드 안내

- **제출 APK 는 release** (`:fuel-wise:assembleRelease`; 서명한 release APK 는 `apk/` 에 포함). release 에는 API 키가 없고, 시연 수신기·시연 컨트롤(실신호/주행 전환, 시뮬레이션, 샘플 목적지, 샘플 기록)이 **없다**.
- 시연 영상은 **release 에서 실신호(또는 Virtual Console 값)로 촬영**한다. debug 전용 시연 컨트롤은 심사 APK 에 포함되지 않는다.
- 제출 전 확인: `aapt dump badging fuel-wise-release*.apk` 출력에 `application-debuggable` 이 **없어야** 한다(있으면 debuggable 빌드).
- 병합 매니페스트에는 Pleos SDK 가 추가하는 `android.permission.INTERNET` 이 들어간다. **앱 자체는 외부 통신을 하지 않는다**(Remote 오피넷 구현은 골격만, 샘플 데이터는 번들 asset).
- 최소 SDK 28, target 35.
- APK 는 제출용 fork 의 `apk/` 폴더에 있다. API 키 등 비밀값은 저장소에 없고 release 는 키 없이 동작한다. 자체 서버가 없어 서버 소스도 없다.

## 실행 방법

필요한 것: JDK 17, Android SDK(compileSdk 35). 디자인시스템·`:core`·SDK 의존성이 이 저장소에 포함되어 있어 `app/` 만으로 단독 빌드됩니다. (Pleos SDK 는 공개 Maven 저장소 `nexus-playground.pleos.ai` 에서 받으므로 빌드 시 인터넷이 필요합니다.)

```bash
export JAVA_HOME=<JDK 17 설치 경로>
export ANDROID_HOME=<Android SDK 경로>      # 또는 app/local.properties 에 sdk.dir=<Android SDK 경로>
cd app
./gradlew :fuel-wise:assembleDebug              # 디버그 APK: fuel-wise/build/outputs/apk/debug/
./gradlew :fuel-wise:assembleRelease            # 릴리스 APK: fuel-wise/build/outputs/apk/release/
```

`local.properties` 는 개인 환경 파일이라 저장소에 포함하지 않습니다(`.gitignore` 로 제외). 환경변수 `ANDROID_HOME` 을 쓰면 만들 필요가 없습니다.

### 설치·실행

```
./gradlew :fuel-wise:assembleDebug :fuel-wise:assembleRelease :fuel-wise:testDebugUnitTest
adb install --user 10 -r fuel-wise/build/outputs/apk/debug/fuel-wise-debug.apk
adb shell am start --user 10 -n com.hmgcarapp.fuelwise/.MainActivity
```
첫 실행 권한은 **정차 중** 허용해야 한다(주행 중에는 시스템 권한 대화상자가 막힘).

시연 주입(adb, **debuggable 빌드 전용**, `android.permission.DUMP` 보호 수신기 -> adb shell 만 가능; 300ms 안의 연속 전송은 무시): `adb shell am broadcast --user 10 -a com.hmgcarapp.fuelwise.SIM -p com.hmgcarapp.fuelwise --ei fuel 12 --es mode FUEL --es drive DRIVING --ez alert true`
- `fuel`/`soc`/`range` 는 `--ei`/`--ef` 어느 쪽이든 숫자로 받는다(-1 = 해제, 범위 밖·형식 오류는 로그에 사유를 남기고 무시). `mode` 는 AUTO/FUEL/EV(메모리 전용, `clear` 로 해제), `drive` 는 DRIVING/PARKED.
- `accept` 등 시연 입력은 시스템 주도 경로라 주행 가드를 의도적으로 적용하지 않는다(음성 수락과 동일).

## 테스트 실행

```bash
cd app
./gradlew :core:test :fuel-wise:testDebugUnitTest
```

JVM 단위 테스트이며 에뮬레이터가 필요 없습니다. 결과 리포트는 `*/build/reports/tests/` 에 생성됩니다.

## 에뮬레이터 설정

Pleos Connect 에뮬레이터(Android Automotive 기반)에서 동작을 확인합니다. 설치 방법과 Virtual Console 사용법은 [에뮬레이터 가이드](docs/guide/03-emulator-setup.md)를 따릅니다. 첫 실행 시 Pleos 차량 정보 권한 대화상자가 뜨면 허용해야 합니다.

테스트 환경 메모: 개발과 검증은 아래 환경에서 했고 실차에서는 검증하지 않았다. 단위 테스트 수는 최신 빌드 로그 기준이다.
- Pleos Connect 에뮬레이터: Pleos Connect v2.1.0 (AVD 이름 pleos21)
- Android: 14 (API 34, Android Automotive 기반 Pleos Connect 시스템 이미지)
- 화면 규격: 2560x1440, 160dpi(AVD 설정 기준, 기기 이름 Pleos_Connect_v2_0), 가로(Landscape). 세로 화면은 확인하지 못했다(미확인)
- 사용자: 10 (운전자 프로필)
- 빌드 환경: JDK 17, compileSdk 35 / targetSdk 35 / minSdk 28
- 검증 방법: Pleos Connect 에뮬레이터 + Virtual Console(EV SoC·주행가능거리·기어·속도 변경), debug 빌드의 adb 시연 주입, JVM 단위 테스트
- 실차: 미검증
- 에뮬레이터 실행 파일·Android Studio 의 정확한 빌드 번호: 미확인

## APK

릴리스 APK 는 `apk/` 폴더에 있습니다(`apk/<팀명>_<앱이름>_release.apk`).

## 구조

```
app/
├── fuel-wise/           # 앱 모듈(:fuel-wise)
├── core/               # 공통 라이브러리(:core) - Pleos SDK 연결·차량 상태 어댑터
├── designsystem/       # Pleos 디자인시스템 소스 복사본(:designsystem), 라이선스 포함
├── licenses/           # 서드파티 라이선스(Asta Sans OFL 등)
└── gradle/             # 버전 카탈로그, Gradle wrapper
planning/               # 기획서 (접수양식 02장 8개 항목)
apk/                    # 릴리스 APK
docs/, submission/      # 공모전 기반 자료(원본 유지)
```

- **연결**: SDK 연결·복구(세대·백오프·안정 후 리셋·사망 감지·교체 간격)는 core `ManagedConnection` 하나가 맡는다. 속성·UX·위치·기어·에너지·내비 어댑터는 생성/폐기와 정책값만 지정한다.
- **알림·화면**: 알림·음성·배너·팝업·토스트의 상태 전이는 순수 reducer `AlertFlow` 에만 있고, `AlertRunner` 가 효과를 TTS·STT·내비로 실행해 결과를 이벤트로 되먹인다. `UiState`·`SimReceiver`(adb 시연)는 `AppController` 에서 분리돼 있다.
- **저장**: 앱 시작 때 한 번만 읽는다(정상/손상 격리/읽기 오류 시 이번 실행 저장 보류; 쓰기 실패도 같은 보류). 세션 중 재읽기·병합은 없고 보류 회복은 앱 재시작 또는 '기록 모두 삭제'뿐이다.

## 데이터 출처

**충전소**는 `assets/ev_stations.json`(한국환경공단 『전기자동차 충전소 정보』, 공공데이터포털 data.go.kr, **공공누리 제1유형·출처표시**, 기준일 2026-11-11, 전국 3,103곳: 0.1° 격자마다 급속 2곳+완속 1곳을 골라 담은 대표 표본이며 전수가 아니다)의 **스냅샷**이다(변환기: `apps/scripts/data-snapshot`). 원본에 가격·대기시간이 없어 **요금은 가정 단가 320원/kWh, 대기는 0분 가정**이며 실제와 다를 수 있다. 실시간 사용 가능 여부가 아니다. 출처: 한국환경공단(공공누리 제1유형), 가공·편집됨. 스냅샷 파일이 없거나 깨졌거나 0건이면 기존 가공 샘플 충전소 5곳으로 폴백한다. **주유소(유가)** 는 `assets/stations_sample.json` 의 **가공 샘플**(서울 강남 주변 좌표 10곳, 가상 브랜드)이며 오피넷 원본이 아니다(오피넷 이용약관이 사전 승낙 없는 복제·유통과 가공·판매를 금지(제15조①2·제13조②)하여 스냅샷 번들을 하지 않았다). 화면 라벨은 충전소/유가를 분리해 표시한다. 급속 판정은 원본 라벨이 아니라 kW(50 이상) 기준이다. 충전소 스냅샷 화면(헤더·목록 상단의 출처·가정 단가 표기, '요금 비교 불가' 배지, 설정의 데이터 출처 패널)은 기본 위치(강남 샘플 좌표) 기준으로 에뮬레이터에서 확인했다. 위치를 서울·인천·수원·부산 등으로 바꿔 본 지역별 결과와 '수도권 밖' 안내는 에뮬레이터가 위치 변경을 앱에 전달하지 않아 확인하지 못했다(미확인). 항목 단위로 가격(0 초과·상한)·좌표 범위를 검사해 불량 항목만 건너뛴다. Remote(오피넷) 구현은 골격만 있어 **API 키가 있어도 데이터 라벨은 항상 '가공 샘플'** 이다(실제 후보도 번들 샘플).  API 키(`fuelwise.apiKey` 또는 `FUELWISE_API_KEY`, debug 전용)가 없으면 Fake 를 쓴다. 키는 코드에 넣지 않으며 HTTPS 만 허용. **시연 위치는 서울 강남 인근**(주유소 샘플 범위). 충전소는 전국 스냅샷이라 어디서든 후보가 나오지만 주유소는 강남 일대에만 있고, 바다 등 데이터가 없는 곳에서는 후보가 비어 안내 문구가 표시된다. 이름·좌표가 같은 충전소 7건은 kW 가 큰 쪽 하나만 쓴다.

## 개인정보 처리

- **개인정보 고지**: 이 기기에 저장되는 것은 설정, 선택한 카드, **주유소/충전소명·시각·수량·금액(추정 절약 포함) 기록**, **마지막으로 본 화면과 선택한 후보 id**, 알림 재무장 상태, '음성 응답 사용' 설정이다. **이 기기에만, 평문(암호화하지 않음)으로** 저장하며 **앱 자체는 서버로 전송하지 않는다**(Pleos SDK 가 시스템 서비스와 주고받는 통신은 이 고지의 범위 밖). **암호화는 적용하지 않았다(알려진 한계).** 기록은 최근 500건만 유지한다.
- **현재 위치 좌표는 저장하지 않는다**(현재 위치는 메모리에서 후보 비교에만 사용). 다만 사용자가 '주유/충전 완료 기록'을 누른 건의 주유소·충전소 이름과 시각·수량·금액은 방문 이력에 해당하며, 최대 500건을 오래된 기록의 자동 삭제 기간 없이 평문으로 저장한다(설정에서 모두 삭제 가능, 서버 전송 없음). STT 원문·방문지 이름은 release 에서 로그에 남기지 않는다.
- 초기화: 정차 중 `설정 > 저장된 기록 > 기록 모두 삭제` 또는 `리포트 > 기록 모두 삭제`(같은 문구, 확인 팝업 뒤 삭제; 주행 중에는 비활성). **저장 파일뿐 아니라 손상 보존본(`.corrupt`)과 임시 파일(`*.tmp`)까지 모두 지운 뒤 설정만 다시 기록**한다. 앱 데이터 삭제로도 전부 지워진다. 앱을 켤 때 임시 파일(`*.tmp`)은 모두 자동으로 정리한다. **'기록 모두 삭제'는 리포트 기록·손상 보존본·임시 파일을 지우며, 설정·카드·마지막 화면·마지막으로 선택한 후보 id 는 지우지 않고 유지한다**(후보 id 는 후보 목록의 키이며 방문·결제 기록이 아니다). 손상 보존본(`.corrupt`)은 **다음 정상 저장 때 삭제**되며, 7일은 그 사이 저장이 없을 때의 상한이다.
- 시연 상태(시뮬레이션 잔량, 시연 모드, 주행 강제)는 저장하지 않으며 앱을 켜면 항상 실신호로 시작한다.
- 저장 파일이 손상되면 `.corrupt` 로 보존하고 기본값으로 시작하며 안내 토스트를 한 줄 띄운다(앱은 주행 상태로 시작하므로 주행 중이면 보관했다가 **정차 시 한 번** 표시하고, 손상 보존본이 남아 있는 동안(첫 정상 저장 전까지, 보통 수 초) 설정 > 저장된 기록에도 안내가 표시되며 그 뒤에는 토스트로만 알린다). **일시적인 읽기 오류(I/O)** 는 손상으로 보지 않는다: 보존·삭제 없이 기본값으로 동작하고 **이번 실행 동안은 저장하지 않아** 정상 원본을 덮어쓰지 않는다(같은 실행 중에는 다시 읽지 않는다: 일시적인 오류여도 앱을 다시 시작하거나 '기록 모두 삭제'를 해야 저장이 다시 켜진다). **저장 쓰기가 실패해도(디스크 가득 등) 같은 방식으로 이번 실행 저장을 보류**하고 같은 안내를 띄우며, 이후 '완료 기록'은 '기록됨(이번 실행에서만 유지)'으로 알린다. 보류 중에는 설정 > 저장된 기록에 안내가 계속 표시된다.

## 알려진 한계

- **기어 신호 오류 시 동작**: 기어 읽기 오류가 나면 마지막으로 확인된 기어를 유지하다가 복구되지 않으면 UNKNOWN 으로 바꾼다. 유지 시간은 **비대칭**이다: 마지막 기어가 P 이면 5초(P→D 전환을 오래 가리지 않도록), D/R/N 이면 30초(주행으로 간주하는 안전한 방향). UNKNOWN 이면 속도·UX 제한으로 다시 판정하고, 둘 다 확인되지 않으면 주행으로 간주한다. 서비스 사망 복구·실기 동작은 에뮬레이터 확인 대기.
- 설정 탭 '차량 신호 상태(SDK 실측)' 패널은 debuggable 빌드에서만 보이며, 원문 진단(예외 클래스명·메시지·16진 property ID)은 debuggable 에서만 그대로 보인다. 그 외에는 고정 문구('이 차량에서는 제공되지 않아요' / '값이 아직 없어요' / '읽지 못했어요')만 쓰도록 했다. 상태 분류는 진단 문자열의 부분 일치에 의존하므로 SDK 메시지 형식이 바뀌면 '읽지 못했어요'로 떨어질 수 있다(표시 전용이며 앱의 판단에는 쓰이지 않는다). 전기차 프로파일 에뮬레이터는 연료 신호를 지원하지 않는다.
- 연결 실패 계열 오류 힌트는 일부러 넓다: `IllegalStateException` 을 서비스 사망으로 볼 수 있어 불필요한 재연결이 생길 수 있지만 안전한 방향이다(알려진 한계, 영향은 재연결 시도뿐).
- **잔량 알림은 앱이 실행 중일 때만 동작한다(포그라운드 서비스 없음)**. 앱이 종료되면 알림·음성 안내가 없다.
- **신호는 3초 주기 폴링 구조**(리스너/구독 아님). 일시 실패는 30초까지 마지막 값을 유지하지만 그 뒤에도 신호가 없으면 설정값(가정 잔량)으로 표시한다. **가정 잔량은 화면 표시용이며 알림 판단에는 쓰지 않는다**(실신호가 있을 때만 잔량 알림). 서비스가 재시작되면 에너지 폴링(무응답 연속 시 포트 교체)·내비 연결(10초 무콜백 시 재생성)·차량 속성/UX 제한 읽기(5~10초 간격 재연결)가 자동 복구를 시도한다.
- 우회 거리는 직선거리x1.3 근사이며, NaviHelper 의 잔여거리/ETA 로 보정하지 않는다(미구현; 남은 거리 값은 단위 미확인이라 계산에 쓰지 않음). 목적지 질의(getDestinationInfo)는 에뮬레이터에서 내비는 후보 경로를 표시하지만 앱이 경로 완료 이벤트(onRoutingCompleted)를 받지 못해 시간 초과 처리됨(안내 중에도 isRouting=false 만 보고되어 목적지 질의 분기에 도달하지 못함). 그래서 실제 응답을 확인하지 못했고 실차 미검증이다. 응답이 없으면 현재 위치 기준 왕복 우회로 동작한다.
- 활성 경로가 있을 때만 경유지로 추가한다. 경로 상태를 알 수 없으면 기존 경로를 덮어쓸 수 있음을 묻는다. 내비 이벤트에는 요청 ID 가 없어, 시간 초과 직후 시작한 새 요청에 이전 요청의 늦은 이벤트가 섞일 수 있다.
- 전기차 '실시간 사용 가능 여부'는 미지원(정적 대기시간 값만). 내연기관에는 시간 비용 옵션이 없다.
- 리포트는 사용자가 누른 '완료 기록'만 반영한다(자동 감지 아님).
- 알림 재무장은 **값이 있는 신호가 모두** 회복 마진(잔량 +10%p, 주행가능거리 x1.5)을 넘어야 이뤄진다. 신호가 null 이면 나머지 한쪽만으로 재무장될 수 있다. 연료/전기 알림은 하나의 `armed` 를 공유한다.
- 주행가능거리를 알면 목적지 방향 확장 후보(20km 밖)는 현재 위치에서 주행가능거리 이내로 제한한다. 목적지 질의 예외는 로그만 남기고 내비 연결을 폐기하지 않는다. 안내가 끝나도 목적지가 최대 30초 남을 수 있고, 일시적으로 경로 상태를 알 수 없으면 직선 근사로 잠시 전환(깜빡임)될 수 있다(알려진 한계).
- 후보 반경은 20km(활성 경로 목적지가 있으면 목적지 방향 60km·우회 3km 이하 후보 추가). 후보는 번들 데이터 전체(충전소 3,103곳 중 중복 제외, 주유소 샘플 10곳)를 선형 스캔하며 원격 조회는 미구현. 주유소 샘플 데이터는 서울 강남 인근에만 있고 충전소는 전국 스냅샷이다. 설명과 시연에서는 '경로상'이 아니라 **'경로 부근(직선거리 근사)'** 이라고 표현한다.
- 개인정보(**현재 빌드 기준**): 방문지명·시각·금액은 평문 저장(암호화 미적용, 이름 암호화는 보류). 저장 항목이 늘면 이 고지를 함께 갱신한다.
- 에뮬레이터 한계: 내연기관 연료 신호 없음(시뮬레이션 값 사용), 내비는 후보 경로를 표시하지만 앱이 경로 완료 이벤트(onRoutingCompleted)를 받지 못해 시간 초과 처리됨(FuelWise 에서는 안내 중에도 isRouting=false 만 보고되어 목적지 질의 분기에 도달하지 못함) — **경로 완료·경유지 추가 성공은 검증하지 못함**(요청 호출·분기·문구·오류 이벤트까지만), 음성 "응" 실제 인식 결과 없음, Portrait 실화면 증거 없음.
- 기준(우회 최소) 후보와 비교 대상 중 하나라도 가정 단가면 절약 금액·'실질 절약' 표기·음성·배너 절약 문구를 쓰지 않고 '요금 비교 불가'로 둔다(혼합 목록 포함). 가정 단가 목록의 정렬 첫 탭은 '우회·대기 기준 순'으로 표기한다(주유소 목록은 '실질 비용순' 그대로).
- 알려진 한계: 이전에 기록한 항목과 가정 단가 기록을 목록에서 구분해 보여 주지 않으며, 리포트 누적 안내 문구는 가정 항목을 합계에서 뺐다는 점만 알린다. 스냅샷 `_meta` 가 불완전하면(출처·날짜 일부 누락) 표기가 간략해질 수 있다.
- **권한 대화상자와 주행**: 앱은 시작 때 런타임 권한이 없으면 주행 상태와 무관하게 요청한다. 권한 대화상자가 떠 있는 채로 주행이 시작되면 **플랫폼이 그 대화상자를 '주행 중에는 사용할 수 없습니다' 차단 화면으로 덮으며** 앱 영역이 가려진다(앱 결함이 아닌 플랫폼 동작: 권한을 모두 부여하면 알림 진행 중 P→D 전환 5/5 정상). 설치 직후에는 **정차 상태에서 권한을 먼저 허용**한다.
- (DEFER) 주행 중 헤더의 데이터 라벨(dataShort)이 후보 비동기 로드 뒤 길어질 수 있어 에뮬레이터에서 줄바꿈/말줄임을 확인해야 한다.
- (DEFER) `SampleJsonParser.isFast` 는 현재 호출처가 없다(급속 판정 상수만 유지).
- (DEFER) 후보 데이터 이중 로드 가능성(앱 시작과 첫 위치 갱신)은 캐시로 비용만 줄였고 구조는 그대로다.
- (DEFER) 성능 테스트의 평균 200ms 상수는 개발 기기 기준 여유값이라 느린 CI 에서는 조정이 필요할 수 있다.
