# 알뜰주유 FuelWise 기획서 (접수양식 02장 초안)

> 팀명·대표자·연락처 등 참가자 정보는 **접수양식 01에 기재**합니다(이 문서에는 쓰지 않음).
> 이 문서의 "동작"은 모두 **Pleos Connect 에뮬레이터, 가공 샘플 유가, 충전소 공공데이터 스냅샷(요금은 가정 단가)** 기준입니다. 실차·실시간 가격 연동 결과가 아닙니다.
> 표기: **[기획 가정]** = 기획 원문의 가정(검증하지 않음), **[구현]** = 코드·테스트로 확인, **[미구현/미검증]** = 6장 한계 참조.

## 1. 앱 한 줄 소개

주유소·충전소를 '가격'이 아니라 **우회에 드는 연료(전력)비까지 합친 실질 비용**으로 비교해 추천하고, 잔량이 낮아지면 음성으로 알려 내비게이션 안내/경유지로 연결해 주는 차량용 앱입니다.

## 2. 기획 배경

- **주목한 순간**: 리터당 단가가 싼 주유소를 찾아 돌아가면, 우회에 쓴 연료와 시간 때문에 오히려 손해일 수 있습니다. 가까운 순/가격 순 정렬만으로는 운전자가 거리와 가격을 머릿속으로 계산해야 합니다. 전기차는 충전 요금·출력·대기까지 겹쳐 판단이 더 복잡합니다. (기획 원문의 문제 인식)
- **왜 차량인가**: 차량은 잔량(연료/배터리 SoC)·주행가능거리·현재 위치를 알고 있어, 운전자가 검색하지 않아도 필요한 순간(잔량 임계)에 먼저 제안할 수 있습니다.
- **주행 안전 관점**: 운전 중 가격 비교 화면을 만지게 하는 대신, 비교는 정차 중에 하고 주행 중에는 짧은 음성 안내와 한 줄 배너만 제공하도록 설계했습니다.

## 3. 주요 기능 및 차량 특화 요소

| 기능 | 내용 | 상태 |
|---|---|---|
| 실질 비용 계산 | 총비용 = 단가 x 주입량 + 우회 연료(전력)비. 기획 예시(40L, 단가차 30원, 왕복 6km, 12km/L)에서 실질 절약 350원을 단위 테스트로 재현 | [구현] |
| 후보 추천 | '경로상'이 아니라 **경로 부근(직선거리 근사)**: 현재 위치 20km 이내 후보를 직선거리 x 1.3 왕복 우회 근사('왕복 추정(목적지 없음)')로 비교. 내비 안내 중이면 읽기 전용 목적지 질의로 받은 목적지를 넣어 '경로 추정 우회(직선 근사)'로 비교하고(목적지 방향 60km·우회 3km 이하 후보 추가), 응답이 없으면 왕복으로 폴백. 연비·전비는 차량 실측이 아니라 **사용자 설정값** 기반. 절약액의 비교 기준은 '근처 최저가'가 아니라 **우회가 가장 적은 후보** | [구현] 근사 |
| 잔량 알림 | 차량 신호(연료 %, EV SoC, 주행가능거리)가 임계 이하 -> TTS 안내 -> 짧은 명시 응답("응/네/추가해줘" 등) 1회 청취로 수락 -> 결과 음성 확인 | [구현] |
| 내비 연동 | 활성 경로가 있으면 경유지 추가, 없으면 해당 장소로 안내 시작, 상태 확인 불가면 덮어쓰기 의사를 한 번 더 확인 | [구현] 호출·분기까지 |
| 전기차 모드 | 충전 출력(차량 한도)·대기시간·요금·시간 환산 반영 | [구현] 정적 값 |
| 할인 | 할인 카드/멤버십 등록 반영 | [구현] |
| 절약 리포트 | 월 누적 "추정 절약". 사용자가 누른 '주유/충전 완료 기록' 기준 | [구현] 수동 기록 |

**차량 특화 요소**
- Pleos Vehicle SDK의 연료·배터리·주행가능거리·기어 신호를 알림 판단과 주행/정차 판정에 사용.
- 주행/정차에 따라 분리되는 UX, 음성(TTS/STT) 중심 수락 흐름, 내비 경유지 연결.
- Landscape 2분할(목록/상세)과 Portrait 1단 레이아웃을 구현(Portrait 실화면은 미검증).

### 주행 안전 설계
- **DO(주의분산 최적화) 선언**: 앱·액티비티에 `distractionOptimized` 메타데이터 선언.
- **정차/주행 UX 분리**: 비교 목록·정렬·설정은 정차 시에만. 주행 중에는 한 줄 배너(40자 이내, 절약액 포함)와 음성 상태 표시만.
- **주행 중 조작 차단**: 주행 전환 시 열려 있던 팝업·상세 화면을 닫고, 주행 중에는 토스트를 띄우지 않음. 독립 검증에서 주행 중 탭 조작이 저장값에 영향을 주지 않음을 확인.
- **fail-safe**: 기어·UX 제한 신호를 모두 확인하지 못하면 주행으로 간주. 앱은 주행 상태로 시작.
- **음성 수락 규칙**: 단어 전체 일치만 수락, 거절 우선, 긴 문장(공백 제외 15자 이상) 차단. 경로를 덮어쓸 수 있는 상황에서는 "바꿔줘" 같은 다음절 명시 표현만 수락(단음절 "응/네"로는 수락되지 않음).
- 음성 응답은 설정에서 끌 수 있음(끄면 배너+TTS만, 마이크 청취 없음).

## 4. 주요 사용 시나리오

**사용자**: 연료비에 민감한 출퇴근 운전자, 충전소 선택이 고민인 전기차 운전자 (기획 원문의 타깃)

**이용 흐름 (에뮬레이터 시연 기준, 위치는 서울 강남 인근. 충전소는 수도권 스냅샷)**
1. 주행 중 잔량(또는 주행가능거리)이 임계 아래로 내려가면 앱이 한 줄 배너와 음성으로 알립니다. 예: "대략 7.9km 우회, 약 1,154원 절약"(독립 검증에서 관찰된 시연 배너).
2. 앱이 내비 활성 경로를 확인해 "경유지로 추가할까요?" 또는 "안내를 시작할까요?"를 묻습니다.
3. 운전자가 "응" 등 짧게 답하면 경유지 추가/안내 시작 요청이 실행되고 결과를 음성으로 알립니다(배너 버튼으로도 수락 가능).
4. 정차 후 비교 목록·상세에서 후보별 실질 비용을 확인하고, 주유/충전을 마치면 '완료 기록'을 눌러 월 절약 리포트에 반영합니다.
5. 후보가 하나도 없는 경우(번들 데이터 범위 밖)는 "근처 후보를 찾지 못했어요"를 1회만 알립니다.

## 5. 개발 계획

**개발 환경**: Pleos Connect 에뮬레이터 v2.1.0(AAOS 기반), Kotlin, Jetpack Compose, 최소 SDK 28 / target 35. 앱 ID `com.hmgcarapp.fuelwise`. 제출 APK는 release 빌드(API 키·시연용 컨트롤 미포함).

**Pleos SDK 사용**

| SDK | 사용처 |
|---|---|
| Vehicle | 연료 %, EV SoC, 주행가능거리, 기어(주행/정차 판정) |
| FusedLocation | 현재 위치 기준 후보 거리 계산 |
| NaviHelper | 활성 경로 상태 확인, 경유지 추가(addWaypoint), 장소 안내 요청(requestRoute) |
| TextToSpeech / SpeechToText | 잔량 알림 안내, 수락 응답 1회 청취(수동 request 방식) |

Pleos 디자인시스템(Compose 모듈 0.2.0)의 컴포넌트와 주행 규제 연동(UX 제한 신호)을 사용합니다.

**구조**: 비용 계산·추천은 순수 로직으로 분리해 단위 테스트, 후보 데이터는 Repository(번들: 유가 가공 샘플 + 충전소 공공데이터 스냅샷, 오피넷 Remote 골격), 알림·음성·배너 상태 전이는 순수 reducer(`AlertFlow`)와 실행기(`AlertRunner`)로 분리, SDK 연결·복구는 공통 `ManagedConnection` 한 곳에서 관리.

**원문 기획 대비 달라진 점**

| 원문 기획 | 구현 결과 |
|---|---|
| 오피넷 가격 API 연동, 서버 캐싱 | 오피넷 Remote는 **골격만(미구현)**. 좌표 변환·키·상업 이용 협의가 필요해 유가는 **가공 샘플**(서울 강남 인근, 가상 브랜드, 원본 아님; 오피넷 약관상 실데이터 번들 금지). 충전소는 한국환경공단 공공데이터(공공누리 제1유형) 스냅샷 1,058곳(기준일 2026-11-11)으로 교체. 앱 자체는 외부 통신을 하지 않음 |
| 경로상 추천, 실제 우회 거리 | 기본은 **현재 위치 기준 20km 직선거리 x 1.3 왕복 우회 근사**. 내비 활성 경로의 목적지(getDestinationInfo)를 받으면 현재->후보->목적지 직선 근사로 평가하며, 실패·무응답이면 왕복으로 폴백. NaviHelper 잔여거리/ETA 보정은 미구현. 목적지 질의의 실제 응답은 에뮬레이터·실차에서 확인하지 못함. 원문 "왕복 6km" 예시는 목적지가 없을 때의 모델에만 해당 |
| 추천 결과를 경유지로 추가 | **활성 경로가 있을 때만** 경유지로 추가. 없으면 직접 안내, 확인 불가면 덮어쓰기 확인 |
| SDK에서 연료 종류·평균 연비 사용 | SDK로 확인할 수 없어 **사용자 설정값**(연료 종류, 탱크 용량, 연비/전비) 사용 |
| 내연기관 연료 잔량 | 에뮬레이터에 내연기관 연료 신호가 없어 **설정값/시뮬레이션**으로 보완. EV SoC·주행가능거리는 SDK 실수신 확인 |
| 충전소 실시간 사용 가능 여부, 충전 요금 API | **미지원**. 원본에 가격·대기시간이 없어 요금은 가정 단가(320원/kWh), 대기는 0분 가정. 사용 가능 여부는 스냅샷 시점 정보도 쓰지 않음 |
| 주행 중 상시 감시 | **앱이 실행 중일 때만** 알림(포그라운드 서비스 없음) |
| 월별 절약 자동 집계 | 사용자가 누른 완료 기록 기준(자동 감지 아님) |

## 6. 기대효과 및 발전 가능성

- **사용자 가치**: 감에 의존하던 주유소 선택을 실질 비용 숫자로 바꿔 불필요한 우회를 줄이는 것을 목표로 합니다. 실제 절감 효과는 실데이터·실차로 측정한 바 없으며, 이 문서는 효과 수치를 주장하지 않습니다.
- **타깃 고객**: 내연기관/하이브리드 운전자, 전기차 운전자, 주행거리가 긴 영업·법인 차량 운전자 (기획 원문).
- **예상 지표 [기획 가정]**: Pleos Connect 적용 10만 대 x 설치율 30% 가정 시 MAU 약 2만 명, 30일 리텐션 45% 목표. 근거 자료가 없는 가정이며 구현·측정 결과가 아닙니다.
- **발전 방향 (미구현)**: 실시간 가격 연동(오피넷/공공데이터, 서버 캐싱·라이선스 협의 선행), NaviHelper 실제 경로·ETA 기반 우회 보정, 충전소 실시간 상태, 정유사·충전사업자 제휴 쿠폰, 법인 차량 연료비 리포트(B2B).

### 품질 체계 (구현 결과)
- 단위 테스트: core 82개, fuel-wise 264개(고유 개수), 실패 0.
- 구조 리팩터링: 연결 복구·알림 상태 전이·UI 상태·시연 수신기를 분리(`ManagedConnection`, `AlertFlow`/`AlertRunner`, `UiState`, `SimReceiver`).
- 코드리뷰 11라운드(마지막 두 라운드 Blocker/Major 0), 반영 후 종료.
- 독립 런타임 검증(제작·리뷰와 무관한 검증, 에뮬레이터): 12개 시나리오 PASS 8 / PASS(일부 UNCERTAIN) 3 / 부분 UNCERTAIN 1 / **FAIL 0**, 크래시 없음.
- 개인정보 고지(저장 항목, 위치 이력 미저장, 기록 삭제 기능)를 명시.

### 알려진 한계 (정직한 고지)
- **환경상 미검증**: Portrait 실화면, 실제 음성 인식 결과(STT "응" 인식), 내비 경로 생성/경유지 추가 **성공**(요청 호출·분기·문구·오류 처리까지만 확인), Pleos 서비스 사망 후 복구의 실기 동작, 내연기관 연료 실신호, 사용자 전환 시나리오.
- 신호는 3초 주기 폴링이며, 일시 실패 시 마지막 값을 30초 유지.
- 유가는 가공 샘플, 충전소는 스냅샷(기준일 2026-11-11, 실시간 아님)이며 요금은 가정 단가다. 후보는 수도권 일대에만 있다(반경 20km). 충전소 데이터 교체 후 실화면은 에뮬레이터에서 확인하지 못했다.
- 가정 단가 충전소 후보는 요금 비교(절약 배지·절약 금액 음성)를 하지 않고 우회/대기 기준으로만 추천하며, 리포트의 가정 단가 항목은 지출을 '실제 요금 아님'으로 표시하고 절약 합계에서 제외한다.
- 저장 데이터(방문지명·시각·금액)는 기기 내 평문 저장(암호화 미적용).
- 권한 대화상자는 주행 중 플랫폼이 차단하므로 설치 직후 정차 상태에서 허용해야 함.
- 병합 매니페스트의 INTERNET 권한은 Pleos SDK 유래이며 앱은 자체 외부 전송을 하지 않음.
